# Final content, engine, storage, privacy, and performance audit

This is the owned requirement audit for the full `SPEC.md`, reconciled against
current source rather than the older Stage A/B checklist labels. It is not a
claim that the full release or the external terminal/platform matrix is complete.
Every scoped stable ID is listed individually below. Application/terminal and
release boundaries are stated where one requirement spans multiple owners.

The runtime freeze is
`31586c3bc81633d5d3f912b7e717800caf185ecfce5358f7feeb92b3aa8129e3`.
The latest integrated transcripts are
`docs/measurements/stage-d-frozen-all-tests.txt` and
`docs/measurements/stage-d-frozen-msrv-all-tests.txt`, checksummed in
`docs/measurements/stage-d-frozen-rust-validation.json`. Both current Rust and
Rust 1.88 passed all 253 tests, including 42 library unit tests, 7 content edge
tests, 61 engine acceptance/property tests, 6 allocation/bounds tests, 21 sample
tests, 29 storage acceptance tests and 23 executable CLI tests. The two Windows
storage fixtures and eight Windows helper tests are target-specific; native
macOS success does not execute them. The independent Windows review and stable
Clippy/MSRV cross-check evidence are in `docs/audit-windows-permissions-review.md`.
The focused content/storage transcripts are retained as earlier checkpoints.
The separately recorded zen-bounds-current-final.log and zen-bounds-msrv-final.log
also pass the new independent repeated-cycle engine oracle on both compilers.
The only intentionally ignored storage fixture is the explicitly invoked release
100,000-row query benchmark; no correctness failure is disguised as an ignore.

The audit found and fixed four concrete edge cases: valid 1 MiB sources whose NFC
representation grows beyond 1 MiB; imported normalized tokens crossing the 8 KiB
or 32-scalar bound; 25-word practice incorrectly reusing the raw-source size limit;
and absent independent practice/paste/auto-indent history filters. Oversized
optional word diagnostics now increase an explicit omission count rather than
losing the result, and recovery exports share the SQL writer's eligibility rule.
The first new cluster fixture used x+diaeresis, which validly composes to ẍ; it was
corrected to q and the suite rerun. This was a fixture correction, not a relaxed
validation rule.

Test names below refer to `tests/kernel_acceptance.rs`,
`tests/kernel_performance.rs`, `tests/sample_acceptance.rs`,
`tests/content_adversarial.rs`, and `tests/storage_acceptance.rs`, or the explicitly
named `src/content` / `src/storage` unit modules. Native OS/emulator compatibility,
physical timing, cold-cache launches, and dedicated controlled-machine baselines
are not inferred from these library tests or synthetic PTY observations.
The companion `audit-primary-final.md` and `audit-terminal-final.md` close local
application boundaries cited below. `measurements/terminal-permissions-final.json`
records 62 actual lifecycle/product/tmux/SSH cases on native ARM64 and 62 under
Rosetta, without failures or skips, plus the exact final production executable's
denied-IP-network save workflow. These remain PTY/translated execution evidence;
native Intel hardware, unavailable operating systems and graphical emulators are
not inferred.
